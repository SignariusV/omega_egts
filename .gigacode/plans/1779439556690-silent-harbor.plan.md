# План: Анализ процесса формирования сценариев верификации

## Фон

Пользователь запросил изучение процесса формирования сценариев верификации в проекте OMEGA_EGTS, с фокусом на варианты создания сценариев и их использование. Иссле��ование показало, что в проекте существует несколько сценариев верификации, реализованных через протокол EGTS (ГОСТ 33465-2015), которые используются для первоначальной настройки УСВ (Устройства Сбора Данных).

## Критические файлы

- `scenarios/verification/README.md` — Описание сценария верификации по SMS.
- `scenarios/verification/scenario.json` — Конфигурация сценария верификации по SMS.
- `scenarios/verification_tcp/scenario.json` — Конфигурация сценария верификации по TCP.
- `scenarios/verification_combo/scenario.json` — Демонстрация трех способов задания пакетов.
- `scenarios/verification_static/scenario.json` — Статическая версия сценария верификации.
- `scenarios/verification_dynamic/scenario.json` — Динамическая версия сценария верификации с переменными.

- Определить и описать все доступные варианты создания сценариев.

- Сосредоточиться на структуре и возможностях формирования сценариев, а не на их выполнении.

## Подход

### 1. Варианты создания сценариев

Анализ показал три основных способа задания пакетов в сценариях:

1. **`packet_file`** (Файл с hex-дампом)
   - **Описание**: Пакет загружается из внешнего `.hex` файла.
   - **Пример**: `"packet_file": "packets/platform/gprs_apn.hex"`
   - **Использование**: Подходит для сложных или часто используемых пакетов, которые удобно хранить в виде бинарных дампов. Обеспечивает точность и позволяет легко редактировать пакеты с помощью hex-редакторов.
   - **Файлы**: `scenarios/verification/scenario.json`, `scenarios/verification_tcp/scenario.json`

2. **`packet_hex`** (Hex-строка в конфигурации)
   - **Описание**: Пакет задается напрямую в виде hex-строки внутри JSON.
   - **Пример**: `"packet_hex": "0100000B002A001C0001AB23..."`
   - **Использование**: Удобен для простых пакетов или когда необходимо включить пакет целиком в конфигурацию без внешних зависимостей. Подходит для тестирования и демонстрации.
   - **Файлы**: `scenarios/verification_combo/scenario.json`

3. **`build.packet`** (Динамическая генерация)
   - **Описание**: Пакет строится динамически из структурированных данных на основе спецификации EGTS.
   - **Пример**: `"build": { "gost_version": "2015", "packet": { ... } }`
   - **Использование**: Наиболее гибкий способ, позволяющий использовать переменные (`{{variable}}`) и создавать параметризованные сценарии. Идеален для динамических тестов, где параметры (например, `unit_id`, `packet_id`) могут меняться.
   - **Файлы**: `scenarios/verification_combo/scenario.json`, `scenarios/verification_static/scenario.json`, `scenarios/verification_dynamic/scenario.json`

### 2. Типы сценариев верификации

- **`verification` (SMS)**: Базовый сценарий для настройки УСВ через SMS-канал (APN, адрес сервера, UNIT_ID).
- **`verification_tcp` (TCP)**: Аналогичный сценарий, но использующий TCP-канал для обмена.
- **`verification_combo` (COMBO)**: Демонстрационный сценарий, объединяющий все три способа задания пакетов.
- **`verification_static` (static)**: Сценарий с полностью статическими значениями, заданными в `build.packet`.
- **`verification_dynamic` (dynamic)**: Сценарий с переменными, объявленными в секции `variables`, что позволяет переопределять их при запуске.

### 3. Рекомендации по использованию

- **Для точного воспроизведения**: Используйте `packet_file`, если у вас есть эталонный hex-дамп пакета.
- **Для простоты и автономности**: Используйте `packet_hex` для небольших пакетов, которые не требуют частого изменения.
- **Для гибкости и параметризации**: Используйте `build.packet` с переменными, особенно в `verification_dynamic`, для создания универсальных тестов.
- **Для тестирования канала**: Выбирайте `verification` (SMS) или `verification_tcp` в зависимости от целевого канала связи.
